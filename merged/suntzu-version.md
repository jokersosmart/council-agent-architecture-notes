# 軍師團・商業兵法：Multi-Agent 架構貼文討論紀錄

- 日期：2026-11-05（台北時間）
- 討論對象：CodeSpace（@yc.tonyliu）的 Threads 貼文〈實戰企業級 Agent 架構：Multi Agent 控管／監控〉
  https://www.threads.com/@yc.tonyliu/post/DfT-xpxoGlJ
- 背景：Joker 正在三條服務主線之間做選擇：判斷服務、天賦陪跑、AI 自動化代工
- 提問：「這邊有我可以參考的部分嗎」

## 共識
1. 這篇是工程架構圖，不是商業建議。可以借它的結構思維，不要整套照抄。
2. 架構分層：控制面板（看板、記憶面板、指令列）、Python 服務層（派任務、記憶、Agent 管理）、執行引擎（Claude Code、Codex 等）與基礎設施（Docker、遠端主機）。
3. Joker 的軍師團本身就是這種結構：Joker 是指令列，軍師長負責分派，各軍師是執行引擎，Notion 判斷案例庫是記憶。
4. 對「AI 自動化代工」最有用：客戶買的是控管、監控、出事查得到，也就是「安心」。
5. 讚數證明有人感興趣，不證明有人願意付錢。
6. 風險：還沒選定主線，就被「大家都在做 Agent」吸成第三條戰線。

## 各軍師重點

### 孫子
- 「知己知彼，百戰不殆」：這篇回答「怎麼蓋」，不是「誰會買」。
- 「我專為一，敵分為十」：多 Agent 控管是你的實，但追「企業級」會分散兵力。
- 可借：把監控與出錯停機當成報價賣點。
- 反思：你要學的是技術怎麼做，還是客戶為什麼付錢？

### 馬克思
- 誰掌握調度與監控，誰就掌握生產過程（詮釋）。
- 做自動化可加收月費，負責監看 agent 有沒有跑錯。
- 用自己的軍師團寫「我怎麼讓一群 AI 各自負責、不打架」，當作品集。
- 反思：你的系統裡，監控現在是誰在做？

### 笛卡兒
- 這張圖是「拆解」的示範：誰下指令、誰分派、誰執行、誰記住。
- 下一步：照這四塊畫出「判斷服務」流程圖。畫不出的那塊，就是還沒想清楚的地方。
- 反思：是想學拆解方法，還是又被第三條主線吸過去？

### 海德格
- 產品原則：「這步只能讀、那步要人點頭」。要不要做，一定由人決定。
- 「會做不難，難的是做得完、做得對、出事查得到」：14 天實驗要記錄對方有沒有往前走一步。
- 下一步：寫三條「哪些步驟 AI 可以做，哪些一定要人點頭」。

### 蘇格拉底
- 最值得參考的是他怎麼宣傳：直接把做出來的東西畫成圖貼出來（約 120 讚、117 分享）。
- 下一步：把軍師團畫成「我怎麼讓多個 AI 幫我做決策」的圖，配三行說明，發上 Threads。三天後看反應：有人問「怎麼做」是接案訊號，問「你怎麼想事情」是教練訊號。
- 反思：如果這篇是你發的，你最希望別人問你什麼？

### 黑格爾
- 借結構思維：分工要有總控、記憶要分開存、先有任務才有引擎。
- 小心「抽象的整體」：看起來完整，卻沒經過真實客戶。
- 下一步：在 Notion 案例庫加三欄（誰負責收斂、對方反應、下次要不要繼續這條主線），連記 7 天。

## 待決問題
用一句話定主線：「我幫＿＿（誰），在＿＿（什麼處境）下，得到＿＿（什麼結果）」。
